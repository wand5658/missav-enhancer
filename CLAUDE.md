# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

An unpacked Chrome extension (Manifest V3), published as **MissAV Enhancer**, that patches one specific site, served from two domains — `missav.ai` and `missav.ws`. Both run the same frontend, so a single set of scripts and selectors covers them. Two unrelated concerns: prevent the page from auto-pausing video when the window or tab loses focus, and restyle the site — edge-to-edge layout on every page, a cover carousel (hero) on the home and list pages, Netflix-style scrolling rows on the home page, one-click filter/sort chips on list pages, and a theater-style video page with recommendation rows right under the player. Every feature can be switched and tuned from a toolbar popup (1.5).

There is no build step, no bundler, no package manager, no linter, and no test suite. The files in this directory *are* the extension — Chrome loads them as-is.

## Development workflow

Load once via `chrome://extensions` → enable Developer mode → "Load unpacked" → select this directory.

After editing:

- **`settings.js` / `pages.js` / `hero.js` / `browse.js` / `browse.css` / `manifest.json`** — reload the extension at `chrome://extensions`, then reload the page.
- **`popup.html` / `popup.css` / `popup.js`** — just close and reopen the popup (`settings.js` too, for the popup side).
- **`anti-pause.js`** — reload the extension **and** reload the page. This script injects at `document_start`; reloading only the extension will not re-run it on an already-open tab, so changes appear to have no effect.

To verify anti-pause is live: open DevTools Console, enable the **Verbose** log level, and switch away from the window. Each suppressed pause logs `[anti-pause] 已阻止一次自動暫停`.

### Releases and docs

The extension is published as **MissAV Enhancer** (manifest `name` / `short_name` / `default_title`, `popup.html`). It cannot go on the Chrome Web Store (adult-content policy), so users install a GitHub Release zip unpacked and update by hand. To release: bump `manifest.json` `version`, commit, push a tag `v<version>`. `.github/workflows/release.yml` refuses a tag that does not match the manifest, zips `manifest.json`, `*.js`, `*.css`, `popup.html`, `LICENSE` and `icons/*.png` into a `missav-enhancer-v<version>/` folder, and creates the release. A new top-level runtime file of another type (e.g. `.json`, `.html` page) must be added to that `cp` line, or the release zip silently lacks it.

Each release is cut as on 1.5.1 / 1.5.2: bump the version on `dev`, merge into `main` with `--no-ff` (`Merge branch 'dev' into main (<version>)`), and tag that merge commit with a lightweight tag. **Every release needs written notes.** The workflow's `--generate-notes` produces only the "Full Changelog" link, so once the release exists, fill it in with `gh release edit v<version> --notes-file …`. Group the notes under headings such as `## Fixes / 修正` and `## Features / 新功能`. Write each bullet in English with a zh-TW line under it, describe the change as users see it (not the commit), and keep the `**Full Changelog**` line at the end. Users update by hand, so the release page is where they learn what changed.

`README.md` (English) and `README.zh-TW.md` are kept in step — a feature or setting change updates both. Screenshots live in `docs/screenshots/` (JPG, popup PNG) at 1920×910 — the viewport of a maximised Chrome window on a 1080p screen, which is the size to match when retaking them — with covers, previews and titles (including the hero's shadow DOM and the video description) blurred before capture. ## Architecture

Two `content_scripts` entries that deliberately run in **different worlds** and at **different times**. This split is the central design constraint:

| File | World | Timing | Can use |
|---|---|---|---|
| `anti-pause.js` | `MAIN` | `document_start` | Page globals (`window.player`), no `chrome.*` APIs |
| `settings.js` | isolated (default) | `document_end` | Second entry, loaded first; defines `globalThis.VHS` (settings from `chrome.storage.sync`). Also loaded by the popup |
| `pages.js` | isolated (default) | `document_end` | Same entry; defines `globalThis.VH` (page detection). DOM only — cannot see `window.player` |
| `hd.js` | isolated (default) | `document_end` | Same entry, before `hero.js`; defines `globalThis.VHD` (HD previews). Uses `chrome.storage.local` |
| `hero.js` | isolated (default) | `document_end` | Same entry; DOM only |
| `browse.js` + `browse.css` | isolated (default) | `document_end` | Same entry; DOM only |

There used to be a `content.js` in the second entry that capped the layout root at an inline `max-width: 150vh` and turned the video page's `div.flex[x-data]` into a column. It was removed in 1.4: `browse.css` now owns both jobs with plain CSS (see below), which also dropped a `MutationObserver` on `document.body`.

`anti-pause.js` needs both properties and neither is negotiable:

- **`world: "MAIN"`** — the interception target is the page's own `window.player`. An isolated-world content script gets a separate `window` and cannot reach it.
- **`run_at: "document_start"`** — it installs an accessor on `window.player` and must win the race against the page's inline script that assigns it. That assignment lives deep in the page HTML, so `document_start` reliably runs first.

### How anti-pause works

The page registers three handlers that pause playback (`window` blur, `document` blur, `document` visibilitychange), but **all three funnel through `window.player.pause()`**, where `window.player` is a [Plyr](https://plyr.io/) instance. So the extension intercepts that single method rather than blocking any events — the events still fire normally, which is why nothing else on the page breaks.

`Object.defineProperty(window, "player", { get, set })` catches the assignment regardless of whether the page writes `window.player = …` or `var player = …`; in the latter case a global `var` declaration does not overwrite an existing own accessor, so the assignment still routes through the setter. The setter replaces the instance's `pause` with a gated version.

**The gate is a user-gesture heuristic**, not a check on focus state: a `pause()` call within `GESTURE_WINDOW` (700 ms) of a `click`/`keydown`/`touchstart`/`pointerdown` is treated as intentional and passes through; anything else is dropped. This is what keeps the user's own pause button and spacebar working while suppressing focus-driven pauses. Do not "improve" this into a focus check — the site's handlers fire *because* focus was lost, so a focus check cannot distinguish them from a deliberate pause.

A second, independent fallback layer listens for `pause` events in the capture phase on `document` (media events do not bubble, but capture still traverses ancestors) and resumes playback when the window lacks focus and no gesture preceded it. This covers code paths that bypass `window.player` and call `pause()` on the `<video>` element directly. It causes a brief visible stutter, so it is a backstop, not the primary mechanism.

### Cover carousel (`hero.js`)

`hero.js` shares the second `content_scripts` entry with `browse.js`, so it adds no extra domain list. It activates on two kinds of page. The home page is recognised by its cards, whose preview video id starts with `preview-home-` — no URL or locale-prefix matching. The pages in `VH.LIST_PAGES` (`pages.js`: `/dm<n>/*`, `/saved`, `/saved/actresses`, `/history`, `/playlists`, `/playlists/<key>`) are recognised by `location.pathname` and collect every `.thumbnail video.preview` on the page. A URL gate is required there because video pages also render recommendation cards as `.thumbnail`; adding a page means adding a regex to `LIST_PAGES`, not a `matches` entry. On both kinds of page the host carries `data-bleed`, which switches the shadow styles to full-bleed (no radius, exactly `100vh` tall — the header overlays its top, so `--h` is `100vh − header` and the top padding adds the header height; below 760px the stacked layout keeps its content-based height); the host's actual position is set by `browse.js`.

- **Data comes only from the rendered DOM** (the HD previews below are the one exception). The site sits behind Cloudflare, so fetching index HTML (the approach better-viewing's home page uses) is not reliable. Each card yields `{id, href, title, tags, cover, preview}`: the id is the path segment of the video's `data-src` (so it does not depend on each page's video id format), the CDN base is derived from the video's `data-src` by dropping `/preview.mp4`, and `cover-n.jpg` (800×537, same as `cover.jpg`) is tried before `cover-t.jpg` (330×222, the list thumbnail). `preview.mp4` is the only preview the CDN serves — 320×180, ~8.7 s, H.264; `preview-hd` / `-720p` / `-1080p` / `-n` / `-l` / `-h` all 404 (measured 2026-09-30) — so the hero frame upscales it. Badges are `x-show` anchors, so only those whose inline `display` is not `none` count.
- **Cards are rendered by Alpine after `document_end`**, so a debounced `MutationObserver` re-runs `refresh()`: re-mount the host if it was removed, collect new cards, start on the first arrival. New items are inserted at random positions after `at`, as in better-viewing's `heroAdd()`.
- **Mount point** is the first card's `div.content-*` layout root (prepended), falling back to before its `.grid`. Each slide's clickable area is an `<a>` that carries no `href` until a pointer button goes down: with a permanent `href` the browser's status bubble showed the URL in the bottom-left corner the entire time the mouse was over the hero, because the whole slide is the link. `pointerdown` sets `href`, and `click` / `auxclick` / `contextmenu` / `pointerleave` remove it on the next tick, so left, Ctrl/Shift and middle click and the context menu's「在新分頁開啟」are all native (a middle or Ctrl click opens a background tab, and a link gets no autoscroll). Enter has no `pointerdown`, so the `keydown` handler navigates itself. The hero lives in a Shadow DOM with inline CSS, so it neither reads Tailwind nor touches any Alpine-controlled property — see the login-modal note below for why that matters.
- **The progress bar's CSS animation is the clock**: `animationend` advances. `sync()` is the single place that decides pause state: hovering does **not** pause (the user asked for that); keyboard focus inside (`:focus-visible`, so a mouse click on the prev/next buttons does not count) pauses only the bar, so Tab can reach「前往觀看」before the slide changes, and the preview video keeps playing; `document.hidden`, less than half the hero on screen (`intersectionRatio`, not `isIntersecting`), or reduced motion also pause the video. The outgoing slide's video is stopped and its `src` removed only after the fade, which is what actually aborts the download.
- **Slide transitions are picked at random** from `FX` (parallax / zoom / flip) on every switch, all over `SWAP_MS` (800 ms, passed to CSS as `--swap`). `show(step)` writes the same `data-fx` and `--dir` (1 for next, −1 for previous) on the incoming and outgoing slides; CSS keys the start state on `[data-fx]:not([data-on])`, the end states on `data-on="1"` / `"0"`. Parallax moves background, frame and text at different speeds; zoom scales the old slide towards the viewer (on top, `z-index: 1`) while the new one rises from behind; flip turns the frame like a card in 3D while the slides cross-fade. Movement uses the individual `translate` property rather than `transform`, because `.bg`'s `transform` belongs to the `drift` animation and the two would override each other. The first slide has no `data-fx`, so it appears without a transition. The old slide is removed after `SWAP_MS + 100`. Under reduced motion every transition is off and the swap is instant.
- **HD previews (`hd.js`, setting `heroHD`, on by default).** The stream is `surrit.com/<uuid>/<360p|480p|720p|1080p>/video.m3u8` (segments are MPEG-TS named `videoN.jpeg`, 4 s each). Chrome plays HLS natively (`canPlayType` → `maybe`), so no hls.js: a `<video>` gets the m3u8 as `src` and seeks, and only the segments around the playhead are downloaded. The uuid is **not** the one on the card (`setPreview('<uuid>')` 404s on surrit) and the Recombee API does not return it — it exists only in the video page: plainly in the player's `thumbnail.urls` (`surrit.com/<uuid>/seek/_N.jpg`), and in the packed `eval(function(p,a,c,k,e,d)…)` script (`unpackAll()`, the fallback). So `VHD.resolve()` same-origin fetches the video page, one at a time. Under Playwright nearly every such fetch got a Cloudflare challenge (`cf-mitigated: challenge`, 403), but in a real browser they passed (8 of 8 in the first user log); each URL is still retried after 2.5 s and 5 s, and 4 failures in a row back off (60 s, doubling to 15 min). Results — `{u, d, th, c, how, picked}` — live in `chrome.storage.local` under `hd:<id>` (`VER` invalidates them); on a video page `hd.js` reads its own HTML into that cache without any request. `hero.js` gives each slide `heroHDWait` seconds (setting, default 3, 1–8 in the popup) to show HD, then plays `preview.mp4`. That budget covers both `resolve()` and the stream starting: a stalled HLS load often fires no `error` (the m3u8 or a segment just never arrives, or a seek never completes), so `montage()` takes a `limitMs` — what is left of the budget, at least `HD_MIN_PLAY_MS` (1 s) — and fails with `stream stall` if no clip is on screen by then. Only time spent playing counts, so a hidden tab or a hero scrolled out of view does not use it up; it resolves the next two slides in advance, so most slides are ready when they appear. With HD on, the host carries `data-hd` and the frame grows from `min(800px, 55%, …)` — 800 is `cover-n.jpg`'s native width, the limit while the 320×180 preview is all there is — to `min(1280px, 66%, …)` (1162 px wide in a maximised 1080p window). Quality `auto` is 720p when the frame's device-pixel width exceeds 900, else 480p (480p costs ~0.5 MB per 4 s segment, 720p ~0.85 MB).
- **Montage playback** (`VHD.montage()`). Like the site's own preview, HD plays a quick-cut montage: `CLIP_S` (1.3 s) of each clip in `c`, then the next. Two `<video class="mv">` take turns — one plays while the other is already seeked to the next clip and waiting — so a cut never waits on buffering; a 50 ms interval does the switching, and if the next one is not ready yet the current clip simply runs a little longer. Only the playing one carries `data-on`, which the shadow CSS makes the only visible one (hard cut, no fade); `frame[data-live]` is set once the first clip is actually at its start, so frame 0 never flashes. The montage object has the same `play()` / `pause()` as a `<video>`, so `sync()` treats it like the preview video; a load error on either element stops it and falls back to `preview.mp4`. Each clip costs one segment, so a slide's first loop downloads about 8 segments.
- **Picking the clips** (`heroHDPick`: `smart` / `even`). The site's own `preview.mp4` is not curated: it is ~1 s cut at each of 10 %, 20 % … 80 % (matched against the scrub thumbnails, 2026-10), and no published research gives a "highlight at N %" rule; `even` reproduces those positions in HD. `smart` fetches the scrub-thumbnail sheets at 15 / 25 / … / 85 % in parallel (6×6 tiles of 300×168, ~200 KB each, `pic_num` tiles over the runtime ≈ one per 2 s) and takes the best `WIN_S` (6 s) window of each, cutting the clip from the window's middle: skin-tone ratio in YCrCb (rising to 0.7, penalised above it — a full-frame warm cast or extreme close-up), plus mean luma change between tiles (capped), rejecting windows with a cut (colour-histogram intersection < 0.55), dark or flat tiles. Fewer than 3 usable windows falls back to `even` (`picked` stops it being retried). The user judged the single-clip version's picks as landing on the important parts; `console.debug("[hd] pick", …)` logs every clip's mm:ss for checking by hand.
- `pause` events from the hero's video do not reach `anti-pause.js`'s capture listener on `document`: they are not composed, so their path ends at the shadow root.

### Home / list restyle (`browse.js`, `browse.css`, `pages.js`)

`pages.js` defines `globalThis.VH` — `LIST_PAGES`, `NO_HERO`, `LAYOUT_ROOT`, `kind()` and `hero()` (false on the `NO_HERO` paths, the playlist pages, where both `hero.js` and `browse.js`'s `heroOn()` stand down) — which `hero.js` and `browse.js` both read; scripts in one `content_scripts` entry share an isolated world, so it must stay first in that entry's `js` array. `kind()` returns `"home"` when `div.is-home` exists (a server-rendered class on the home layout root), `"list"` for `LIST_PAGES`, otherwise `null`.

`kind()` also returns `"video"` when a layout root contains `video.player` (server-rendered). That check runs **before** the `LIST_PAGES` match, because video URLs can carry a `dm<n>` prefix too (`/dm2/mida-139`, the form the home page's cards link to); matched as a list page, such a video page got a hero and no theater layout. `hero.js` also returns early for any kind other than `home` / `list`. `browse.js` adds `vh-wide` to `<html>` on every page that has a layout root, then `vh-home` / `vh-list` / `vh-video` by kind, and **every rule in `browse.css` is scoped under those classes** — `content_scripts.css` injects on every page of the domain, so an unscoped rule would leak everywhere. The split is: CSS does all the layout; JS only marks elements, inserts its own nodes, and measures.

- **Never write `display` on anything Alpine toggles with `x-show`** (the login-modal lesson below). Rows hide the `x-show` placeholder card simply by not touching its inline `display: none`. The original list toolbar (`div.flex.justify-between.mb-6`) is hidden with a class because it carries no `x-show` itself.
- **Edge-to-edge layout** (`vh-wide`, all pages): non-home layout roots lose `sm:container`'s `max-width` and centring in favour of `--vh-gutter` side padding. The home root has no `sm:container`; there the same padding goes on each section (`.is-home .sm:container`), which is why the root rule excludes `.is-home`. No `!important` is needed because nothing writes an inline width any more.
- **Rows**: each `div.grid` in the home root gets `data-vh-row` and its parent `data-vh-section`, except the random section, recognised by its `button.button-primary` (好手氣). Rows are flex + `scroll-snap`; `--per` (1.8 / 2.6 / 3.4 / 4.4 by width) sets how many cards fit, the fraction being the deliberate peek. A horizontal scroller clips vertically too, so `--lift` / `--lead` padding with matching negative margins leave room for the hover scale (`--vh-zoom`, 1.3×, mirrored by `ZOOM` in `browse.js`). That is not enough horizontally, so a `pointerover` handler sets each card's `transform-origin` to its left or right edge when the scaled card would cross the row's (or viewport's) edge. The `--lift` overlap covers the bottom of each section's title row, so the title row and the load-more link sit at `z-index: 5`, a hovered card at 6, and the arrows at 7 so an enlarged edge card cannot cover them. The right side bleeds to the viewport edge via `--vh-bleed`, and the arrows use `--vh-edge` / `--vh-pad`; all three are **measured in `layoutRows()`, not `100vw`**, because `100vw` includes the scrollbar and would add a horizontal scrollbar on Windows. Arrows are the extension's own buttons appended to the section, positioned to the row's `offsetTop` / `offsetHeight`.
- **Scroll reveal** (all three kinds): `initReveal()` marks each card's unit — the card's cell in a row or grid (`[data-vh-row] > *, div.grid > *`), which on some grids is the `.thumbnail` itself and in the video sidebar is the `div.flex` item — with `.vh-rv` (transparent, 28px down) and observes it with an `IntersectionObserver` (threshold 0.15). Units entering together are sorted top-to-bottom, left-to-right and get `.vh-in` with `--vh-rv-d` = index × 150 ms (capped at 8), fading up over 800 ms (`REVEAL_MS`, mirrored in `browse.css`); the classes are removed afterwards. `.vh-rv` is applied by `hideForReveal()` with an inline `transition: none` and one forced style flush: units are often already painted, and with the transition on they would fade *out* towards transparent and turn straight back at `.vh-in`, which reads as no animation at all (first seen on the actress grid, which reveals on load). Only `opacity` and the individual `translate` property change, so `display` is untouched and the hover `transform` still composes; when the unit is the `.thumbnail`, its `transition` list repeats the hover properties so neither overrides the other. Cards without a layout box (`getClientRects()` empty) are skipped: the random section's preload cards sit in a `.hidden` `x-ref="preload-container"`, and「好手氣」copies their `innerHTML` verbatim into the grid, so a `vh-rv` marked there would arrive transparent and already flagged, never to be revealed. It runs after `initRows()` in `refresh()`, and not at all under reduced motion. On home and list pages, observation waits for the hero: before it is inserted and shown, the first cards sit in the first screen, would reveal at once, and then be pushed below the fold already visible. The hero's host is inserted with its section `hidden` (shown after the first cover loads, inside the shadow root, invisible to the layout-root `MutationObserver`), so a `ResizeObserver` on the host starts observation once it is taller than 100px; a 3 s timeout covers pages where no hero appears. Cards in a horizontal row reveal as they scroll in sideways, because the observer accounts for the row's clipping.
- **Keyboard**: `tidyCards()` sets `tabindex=-1` on every card link except the title (`.my-2 a`), so Tab stops once per card; ←/→ inside a row moves between cards. The list page already binds ←/→ to page turns (`@keyup.arrow-right.window`), so row keys exist only on the home page.
- **List grid** is widened from the site's 2 / 3 / 4 columns to 1 / 2 / 3 (`grid-template-columns` override, the grid itself has no `x-show`).
- **List toolbar** is rebuilt from the original dropdowns' links: one `role="group"` of chips per dropdown, the active one matched by the text after the label's colon and marked `aria-current`. Its right end is a mini pager (`miniPager()`): ‹ / › links and an editable page number (Enter jumps, Esc or blur restores), so the page can be changed from the sticky toolbar without scrolling to the bottom. Only dropdowns whose label is `名稱: 值` are converted: `/saved/actresses` has a「我的帳戶」dropdown whose items are logout, delete account and `href="#"` links driven by `@click`, which as chips would lose their handlers. When some dropdowns are left, only the converted `.relative` boxes get `.vh-gone` and the original toolbar stays with the rest. Any structural mismatch leaves the original toolbar visible.
- **Actresses** (`/saved/actresses`, in `LIST_PAGES`; `PEOPLE` in `browse.js` when the root has `> div > ul.grid img`): the avatar grid's `bg-nord1` panel is dropped and the `ul.grid` becomes `auto-fill` columns of 136px round avatars that lift and ring on hover; each `li` is a reveal unit, but not observed: with no hero above, all of them go into one `revealBatch` on load, off-screen ones included, and `revealFlush()` staggers them one by one in screen order without the usual cap of 8 (so lower avatars keep arriving at the same pace instead of landing together), each over 1.25× `revealMs` (per-element `--vh-rv-ms`). The single-actress page (`/dm<n>/actresses/<name>`, an ordinary list page) gets its profile block `div.hero-pattern` as a left-aligned glass panel with pill buttons; the favourite button's `bg-primary` (saved, from Alpine's `:class`) becomes the same pink-tinted pill as the video page's active buttons. Neither has `x-show`.
- **Account pages** (`/history`, `/playlists`, `/playlists/<key>`, all in `LIST_PAGES`). `/history` is an ordinary video grid with pagination and gets the hero, grid and pager like `/saved`. The two playlist pages are in `NO_HERO`: the index has no video cards, and a playlist's items are a management view (comment form, delete) whose titles are not in `.my-2 a`. Their toolbar (`div.flex.justify-between.mb-6`) holds only the「我的帳戶」dropdown and a `bg-primary` link (建立片單 / 修改片單), which become pills; the dropdown's inner panel turns dark (its own `x-show` wrapper is left alone). The index's `ul[role=list]` becomes an `auto-fill` grid of glass cards, revealed on load like the actress grid (`LISTS`; `SHEET` in `browse.js` is the `li` selector for both). Each playlist item `li` has `x-show="show"` (deleting sets it false), so it only gets padding, background and `gap` — its row layout is its own `sm:flex` — and it is the reveal unit for its `.thumbnail`; the thumbnail does not scale on hover there, because it would cover the form.
- **List pagination**: `pageInfo()` reads the current page from the pagination's only non-link number and the total from the mobile form's `/ M` span (falling back to the largest `?page=` link); `pageUrl(n)` sets `page` on the current URL. `initPager()` inserts `nav.vh-pager` — large prev/next links at both ends with ←/→ hints, page numbers centred on the current page (`1 … p−2 … p+2 … M`), and a jump-to-page form — and hides the site's `nav` with `.vh-gone` (it has no `x-show`). The hidden `nav` keeps its `@keyup.arrow-right.window` binding working, so `initPager()` only adds a ← / → `keyup` handler for a direction the `nav` has no `@keyup.arrow-*` attribute for (page 1 has no ←). `siteNav()` excludes the extension's own `nav.vh-pager` / `nav.vh-mini`, which are also `nav` elements. Prev/next at either end become a non-link `span[aria-disabled]`; the rest are real links, so middle-click opens a new tab. Below 700px the big buttons keep only the arrow and only the pages adjacent to the current one are shown.
- **Hero bleed** (home and list pages): `placeHero()` resets the host's inline margins, measures, then pulls it to the document's left edge and top (under the fixed, gradient header). `--vh-header` is the header's height from a `ResizeObserver`; the sticky list toolbar uses it too.
- **Ads**: in-flow banners are `.pt-16.pb-4.px-4:has(iframe)`; the corner slot is `body > .fixed.right-2.bottom-2`, matched by position only because it rotates between an iframe and an `<a><img>` banner (the old `:has(iframe)` missed the banner); a third-party live-cam popup is a `body` child with CSS-module hashed classes, matched by the `bottomRight--` prefix; the live-cam strip above the footer is a 300×250 tsyndicate slot, `div.space-y-5.mb-5:has([id^="ts_"], script[data-ts-spot])`. Matched by structure, not ad domain — the extension has no network blocking, which is how AdBlock hides most of these (its lists block the creative domains, so the slots stay empty). None of these have `x-show`. Hidden under `html.vh-hide-ads` (setting `hideAds`) with `data-vh-kind` picking the page, so it works with the restyle off. `browse.js` sets `vh-hide-ads` before the page-kind check, so the rules that need no `data-vh-kind` (corner slot, live-cam popup and strip) also apply on pages it does not recognise. Hiding them has a side effect: each recommendation section's「載入更多」(`div.absolute.w-full.text-center[x-show]`, the section's next sibling) was absolutely positioned over the following ad wrapper's `pt-16` gap, so without the ad it sat under the next section and could not be clicked. `browse.css` puts it back in flow (`div:has(> div.grid) + div.absolute…`, also under `vh-hide-ads`) by changing only `position` — its `display` belongs to `x-show`.
- **Home search block** (root's `div.flex-col` containing `div > form`) is hidden; the header's search toggle remains. That container has only a `:class` binding (`pb-8`), no `x-show`.
- One debounced `MutationObserver` on the layout root (not `body`) re-runs `refresh()`: recommendation cards and the hero arrive after `document_end`.

### Video page (`vh-video`)

The page's `div.flex[x-data]` holds the sidebar (`div.order-last`, server-rendered inline `max/min-width: 300px`) and the main column (`div.flex-1.order-first`), whose children are: the player block (first `div[x-data]`), `div.mt-4` (h1 + 收藏/片單/分享), the share and playlist panels (`x-show`), `div.under_player` (ad), `div.mb-8` (詳情/磁力下載 tabs) and `div.relative.overflow-hidden` (related grid, with an ad iframe above it).

- **Grid with `display: contents`**: `div.flex[x-data]` becomes a one-column grid and the main column `display: contents`, so the sidebar and the main column's children are siblings that `order` can interleave without moving DOM. Neither element has `x-show`. The share/playlist panels do, so they only get `order`.
- **Order**: player → 接著看 (the sidebar) → title/buttons → panels → details → 相關影片. The text blocks are capped at 1280px wide. The title block (`div.mt-4`) is `position: relative; z-index: 5`: the 接著看 row's bottom `--lift` (44px) reaches into it, and the row's section is positioned, so its transparent scroll container painted over the title's top and swallowed clicks. The share and playlist panels sit at the same level and are glass panels; the playlist panel's checkbox rows (`div.h-5`, name and box squeezed into one 20px line) get a taller hover row and pink checkboxes.
- **Both recommendation blocks are one list**: the sidebar renders `recommendItems.slice(0, 13)` and the related grid `slice(13, 29)` on desktop, so they never overlap and the sidebar holds the higher-ranked half — which is why it, not the related grid, sits under the player. They are separate Alpine `x-for` containers, so they stay two rows; nodes are not moved into one (moving `x-for` output risks Alpine's later re-renders). On non-desktop the site slices both from 0 and they duplicate, so the sidebar keeps Tailwind's `hidden lg:flex` below 1024px and is set to `display: block` only above it.
- **Sidebar as a row**: its inner `div` is a row (`rowGrids()` returns it plus the related grid). Each `div.flex.mb-6` item becomes a column card; the thumbnail and title wrappers carry server-rendered inline widths (165px / 119px, not Alpine-bound), overridden with `!important`. Its title link sits outside `.thumbnail`, so `cardTitle()` looks in the item's `div.flex-1`, and `refresh()` runs `initRows()` before `tidyCards()` on this page. The sidebar's ad `div.space-y-6` is hidden.
- **Theater band**: the player block is stretched to the viewport with negative `--vh-gutter` margins; its children are capped at `--vh-player-w` = `(100vh − player top − 12px gap) × 16/9` (min 480px) and centred, so the picture ends just above the bottom of the window; the loop bar sits below the fold. The player top (`--vh-player-top`) is measured by `browse.js` (`measurePlayer()`, on refresh and resize), because the header height alone misses the layout root's top padding and the picture got cut off by the window's bottom edge. The layout root's own top padding (site CSS: 80px, 56px when narrow) is replaced on this page by header height + 8px, so the gap above the player is small. Plyr fullscreen uses its own container and is unaffected.
- **Ambient light**: `browse.js` writes the video's cover (`og:image`, falling back to `video.player[data-poster]`, both server-rendered `cover-n.jpg`) to `--vh-cover` on `<html>`, and three blurred copies of it replace the black band: a full-page `position: fixed` wash (`body::before`, z −3) with a vignette (`body::after`, z −2), a top glow on the player block's `::before` (z −1, fades out by mask over 150vh), and a halo behind the player wrapper's `::before` that slowly breathes (off under reduced motion). The site's dark gradient is a `body` background with none on `html`, so it propagates to the canvas and negative-z pseudo-elements paint above it and below all content. The player block must therefore **not** be a stacking context: `isolation` there would turn the top glow into a normal layer painted over the title and details. It clips horizontally (`overflow-x: clip`) because the scaled halo would otherwise add a horizontal scrollbar; the loop bar sits at `z-index: 1` above the halo's spill. The action buttons (`button` and the download `a`) are pills: the site marks the active one — saved, or the playlist / share panel open — with `text-primary` from `:class`, and the pill's own `color` would hide that, so `.text-primary` gets pink text, a faint pink fill and an inset ring (`box-shadow`, not `border`, so toggling does not shift by 2px). The pink is `--vh-primary`, measured by `browse.js` from a probe `span.text-primary` (default `#fe628e` in `browse.css`), mixed with `color-mix()`. The action buttons and the details tab box are glass panels (translucent + `backdrop-filter`). The wash and vignette also apply on `vh-home` / `vh-list`, where `hero.js` sets `--vh-cover` to the current slide's cover on every slide change; Chrome cross-fades the `background-image` transition, so the page tint drifts with the carousel. There the full-bleed hero has a transparent ground and masks its `.bg` and overlay to transparent at the bottom, so it fades into the tinted page instead of ending in a hard edge.
- **Details**: the promo `ul.list-none` is hidden; each `div.space-y-2 > div.text-secondary` row is a wrapping flex with a hanging-indent label, and `font-size: 0` on the row (reset on children) hides the bare-text commas between links. That is why the indent is `--vh-label-w` in px: an `em` on the row resolves to 0 while the label's own `em` is 14px, which pushed the labels out of the column.
- `browse.js` removes the sidebar's inline width (CSS cannot beat it; Alpine does not manage it) and inserts the「接著看」/「相關影片」headings before each row; the related section's `overflow-hidden` is overridden so the bleed and hover scale are not clipped. In sidebar cards the title is outside `.thumbnail`, so the hover scale (and panel background) goes on the whole `div.flex` item instead, the `.thumbnail` hover rule excludes `.order-last`, and the `pointerover` origin handler looks for that item before `.thumbnail`.
- Row ←/→ only act when focus is on a card, so Plyr's own arrow-key seeking is unaffected.
- Ads hidden: `.under_player`, the iframe above the related grid, the sidebar's `div.space-y-6` with iframes, and the corner ad.

### Site coupling

Every script is tightly bound to the target site's internals and will silently stop working if the site changes:

- `anti-pause.js` depends on the global being named `player` and exposing a `pause()` method.
- `hero.js` depends on cards being `.thumbnail` containing `video.preview` whose `data-src` is `<cdn>/<id>/preview.mp4` (on the home page the video id must also start with `preview-home-`), and the title in `.my-2 a`.
- `browse.css` / `browse.js` depend on: the video page structure listed under *Video page*; home root `div.is-home`; sections being the grid's parent with the title row as first child; the random section's `button.button-primary`; the list toolbar `div.flex.justify-between.mb-6` holding `.relative > a > span` labels (`名稱: 值`) and menu `div a[href]`; the fixed header `div.fixed.z-max.w-full`; the pagination inside `nav` (current page as the only non-link number, total as a `/ M` span, `?page=` URLs); the actress avatar grid as root `> div > ul.grid > li` with a `div.rounded-full` avatar and `h4` name, the actress profile block `div.hero-pattern`; the playlist pages' `root > div[x-data] ul[role=list] > li` (index items link to `/playlists/<key>`, playlist items hold a `.thumbnail` and a `form` with `textarea` and `button`s); and the video page's playlist panel `div[x-show*="playlist"] fieldset > div > div.h-5`.

**Why nothing writes `display` on `x-show` elements.** Alpine's `x-show` toggles elements by writing inline `display`. The removed `content.js` once queried `div[x-data].flex` across the whole document and forced `display: flex` on matches; `x-data` marks every Alpine component root, so it fought Alpine for that property on unrelated components, and its `MutationObserver` re-fought it on every DOM change. The observed symptom was the login modal (opened by the favourite button) failing to appear at all — not, as fighting over `display` naively suggests, the element getting forced visible. The rule that came out of it: scope every selector to a layout root or a specific known element, and leave `display` on `x-show` elements to Alpine. When something like this recurs, bisect against the live page rather than reasoning about it — disable one `content_scripts` entry in `manifest.json`, then one block of `browse.css`, and it localises in a couple of reload cycles.

The target domains are listed in three separate places in `manifest.json`: `host_permissions`, and the `matches` array of each of the two `content_scripts` entries (`anti-pause.js`, and `settings.js` / `pages.js` / `hero.js` / `browse.js`). The popup's `SITE` regex in `popup.js` only drives the header status, not where anything runs. Adding, removing, or changing a domain means editing all three lists — miss one and the extension half-loads, which looks like a site-side regression rather than a config error.

### Settings (`settings.js`, `popup.*`)

`settings.js` defines `globalThis.VHS`: `DEFAULTS` (every key and its default — the defaults are the pre-1.5 behaviour, so a user who never opens the popup sees no change), `GROUPS` (master switch → its items), `RELOAD`, `ready` (a Promise resolved once `chrome.storage.sync.get` returns), `get(k)`, `on(k)` (a boolean item counts only if its master is on too), `reduced()` (the `motion` setting — `system` follows `prefers-reduced-motion`, `full` / `reduce` override it), `subscribe(fn)` (fires on `storage.onChanged`), `set`, `reset`, `clean` (drops unknown keys and values whose type differs from the default; used on load, on change and on import). Storage holds only what the user changed; `reset()` is `storage.sync.clear()`.

- **Load order**: `settings.js` is first in the second `content_scripts` entry, and `hero.js` / `browse.js` start inside `VHS.ready.then(...)` / `await VHS.ready`. It is deliberately not a third entry at `document_start`: that would add a fourth copy of the domain list, and nothing that needs settings runs before `document_end`.
- **anti-pause bridge**: `anti-pause.js` runs in the MAIN world and cannot use `chrome.storage`. `browse.js` writes `{on, gestureMs, fallback}` as JSON to `<html data-vh-anti-pause>` (on every page, before the page-kind check) and rewrites it on change; `anti-pause.js` reads and caches it at the moment of each `pause()` call / `pause` event. Until it is written the defaults apply, so the setter is still installed at `document_start` and nothing races the async storage read.
- **Live vs reload**: settings that only change appearance or timing apply live — `browse.js`'s `applySettings()` writes `<html>` classes (`vh-reduce`, `vh-hide-ads`, `vh-hide-search`, `vh-per-fixed`, `vh-cols-2|3|4`, `vh-theater`, `vh-hide-promo`, `vh-ambient`, `vh-breathe`, `vh-tint`, `vh-glass`) and inline CSS variables on `<html>` (`--vh-zoom`, `--vh-per-n`, `--vh-player-gap`, `--vh-halo-a`, `--vh-top-a`, `--vh-wash-a`, `--vh-rv-ms`), which beat the defaults declared in `browse.css` because inline style wins on the same element; `hero.js`'s `applySettings()` writes host attributes (`hidden`, `data-short`, `data-reduce`) and `--slide` / `--swap`, and reads `heroFx` / `heroPreview` when it needs them. Settings that change DOM structure (`RELOAD`: `home`, `homeRows`, `list`, `listChips`, `listPager`, `video`) are read once at load; the popup tags them and offers a reload button.
- **Page-kind classes**: `vh-home` / `vh-list` / `vh-video` now mean "this page's restyle is on". Rules that must work with the restyle off (ads, the home search box) key on `data-vh-kind` instead. Turning the home restyle off still leaves the hero bleed (`placeHero`), ads, tint and scroll reveal working.
- **Reduced motion** is no longer a media query anywhere: `browse.css` uses `html.vh-reduce` / `:not(.vh-reduce)` and the hero's shadow CSS `:host([data-reduce])`, so `motion: full` can override the system preference.
- **Popup**: the UI is generated from a `GROUPS` description in `popup.js` (switches, sliders, single and multiple choice, and `flags` — options that are each their own boolean key, used for 首頁 / 列表頁). Any item can carry a one-line `hint` under its label; a slider can also carry a `note`, a longer box under the row (`\n` breaks lines), for settings whose right value depends on the user's situation (`heroHDWait`). Strings are zh / en (`lang: auto` follows `navigator.language`). Sliders update their label on `input` and write on `change`, because `storage.sync` limits writes per minute. Every write comes back through `onChanged` and re-renders the popup, which restores keyboard focus by control. The header shows whether the active tab is on the site — `tab.url` is visible without the `tabs` permission because `host_permissions` covers those origins — and `tabs.reload` needs no permission either. Export downloads the full settings as JSON; import accepts only keys and types `clean()` lets through.

### Diagnosing a regression

If auto-pause returns, do not guess at the cause — the mechanism is discoverable from the page. In the Console on a playing video page:

```js
// Which handlers are registered, and what do they do?
for (const [name, tgt] of [['window', window], ['document', document]]) {
  for (const type of ['blur', 'visibilitychange', 'focus']) {
    (getEventListeners(tgt)[type] || []).forEach((l, i) =>
      console.log(`${name}.${type}[${i}] capture=${l.useCapture}`, l.listener.toString().slice(0, 400)));
  }
}

// Who calls pause()? Reproduce after running this, then read the stack.
const origPause = HTMLMediaElement.prototype.pause;
HTMLMediaElement.prototype.pause = function () {
  console.log('pause()', { hidden: document.hidden, focus: document.hasFocus(), stack: new Error().stack });
  return origPause.apply(this, arguments);
};
```

The stack trace identifies whether the pause still routes through Plyr (`wt.pause (plyr.js:…)`) and which page script triggered it. Ignore listeners shaped like `function(h){b.H.stop();g(h);b.dk()&&b.H.start()}` — those are the site's ad/analytics libraries and are unrelated to playback.

## Constraints

- The extension has **no background service worker**. It has an `action` (the settings popup) and exactly one permission, `storage` (sync for settings, local for `hd.js`'s cache), plus `host_permissions`. An earlier version had a `Ctrl+Shift+Q` hotkey backed by `background.js` plus `tabs`/`scripting`/`activeTab`/`windows` permissions; all of it was removed. Adding any other `chrome.*` API call requires adding the matching permission.
- **Icons** (`manifest.json` `icons`, no `action`): `icons/icon.svg` is the source for 32 / 48 / 128 and `icons/icon-16.svg` a simplified 16px variant — the soft glow turns to mush at 16px and disappears on a dark toolbar, so it becomes a full-tile gradient. The PNGs are rendered from the SVGs with headless Chrome (an `<img>` at the target size, `--default-background-color=00000000`, `--screenshot`, then cropped to N×N); re-render all four after editing either SVG.
- `world: "MAIN"` requires Chrome 111 or newer.
- `all_frames` is intentionally omitted: the player lives in the top-level frame, so injecting into ad iframes would be pure overhead.
